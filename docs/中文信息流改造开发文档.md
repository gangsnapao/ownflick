# OwnFlick 中文信息流改造开发文档

日期：2026-11-26

## 一、目标与范围

根据本次需求，将应用收敛为两个主要入口：**信息流、媒体库**。打开 `/` 直接播放媒体库里的视频与图片；取消原首页、音乐电台、下载页及合集等独立产品入口。登录与必要的媒体服务继续保留，不删除已有媒体、收藏或历史数据。产品名称 OwnFlick、Python 包名 spooly、CLI 和环境变量保持兼容。

“全部汉化”覆盖本次保留的页面、按钮、菜单、提示、空状态、无障碍标签、播放器反馈以及相关接口的用户可见错误。用户自己的文件名不翻译。弃用模块不作为保留功能提供。

媒体库支持浏览、搜索、重新扫描、从浏览器选择多个文件导入、删除资源；导入文件进入已配置的媒体目录并建立索引。删除沿用项目回收站策略，不直接永久销毁用户原文件。外部目录中的文件可通过重新扫描纳入索引。

## 二、已核实的现状

- 后端：Flask 应用工厂 `spooly/app.py`，路由按 `spooly/web/` 拆分。
- 数据：SQLite 媒体索引及活动记录，部分历史配置采用 JSON。复用 `LibraryService`、`MediaIndexStore`、`LibraryIndexer` 和 `TrashService`。
- 前端：Jinja 模板、原生 JavaScript 控制器、Tailwind 及按页 CSS。
- 默认入口、音乐电台、媒体库、收藏、下载和设置等现有页面同时存在，导航仍有英文。
- 默认混合流使用推荐选择和图视频比例，还会插入媒体分组，不满足整个媒体库等概率随机的目标。
- 已存在播放进度和信息流会话相关模块，需要核实恢复范围、生命周期保存和失效处理。
- 当前目录为源码快照，没有 `.git` 版本历史；开发不能依赖 Git 回滚或差异命令。

## 三、设计决策

### 1. 入口与中文化

- `/` 展示信息流，`/flow` 保留为兼容入口。
- 桌面与移动端导航均只提供“信息流”和“媒体库”，登录启用时保留“退出登录”。
- 旧首页、音乐、下载、合集等页面不再作为产品入口；历史 URL 跳回主要入口或返回明确的停用响应。
- 保留图片、视频播放，滑动/滚轮切换、进度拖动、清屏等已有适用能力。

### 2. 媒体库管理

- 文件选择器允许多选图片和视频，展示导入进度或处理中状态及成功/失败结果。
- 后端验证媒体扩展名、空文件与目录权限，净化路径，防止路径穿越和覆盖既有文件；同名文件生成新名称。
- 导入采用临时文件及完成后入库，失败清理本次临时数据，返回逐文件结果；仅成功项目参与信息流。
- 删除必须经明确确认，复用回收站与索引刷新；资源删除后会话恢复能跳过失效条目。
- 不新增在线下载、音乐管理、账号系统或云服务依赖。

### 3. 高质量随机信息流

- 随机池为所有已索引、可访问的图片与视频，不以文件添加时间、文件名或媒体类型配额加权。
- 使用系统熵产生至少 128 位种子（优先 256 位）；“随机数要大”落实为足够大的种子空间，而非扩大一个低质量整数的显示范围。
- 同一轮和种子形成稳定的全库随机排列，分页不重复、不漏项；每轮结束重新播种，避免上一轮末尾与下一轮开头立即重复。
- 不将首次请求得到的少量文件反复打乱；媒体库增删后重新校验候选集。
- 在同一浏览器恢复上次队列、当前位置；恢复优先于开启新随机轮次。提供重新打乱操作以主动开启新一轮。

### 4. 退出位置记忆

- 保存当前媒体标识、种子/队列位置、视频当前秒数；图片保存条目位置。
- 在播放中节流保存，并在暂停、切换、页面隐藏和离开时保存，不能只依赖关闭事件的异步网络请求。
- 刷新、关闭后重新打开、进入媒体库后返回，均恢复当前媒体及视频秒数；元数据加载后再定位。
- 本地存储受限、存储内容损坏、资源被删、播放到结尾等情况可安全降级；媒体被删除时跳到有效媒体，不出现空白卡死。
- 默认承诺同一浏览器恢复，不承诺跨设备同步。浏览器自动播放策略可能要求首次点击开启声音，界面必须明确反馈。

## 五、验证方案

- 后端行为测试：根路由与旧入口、中文页面、上传有效/无效/同名/越界文件、删除索引同步、分页全库覆盖、种子稳定与不同种子变化。
- 随机与恢复测试：大于一页的混合媒体库、一轮无重复、轮次切换、媒体库变更、当前媒体被删、损坏存储、视频元数据后定位。
- 前端检查：修改的 JavaScript 语法、生产 CSS 构建；保留有意义的现有测试，因产品收敛失效的旧页面测试按新需求调整。
- 浏览器验证：独立临时媒体库（不动真实资源），导入图片/视频、浏览与删除、滚动切换、刷新与离开恢复、桌面及移动端布局；确认无未处理控制台错误。
- 测试服务必须使用独立数据目录和端口，不替换用户正在运行的服务，不使用项目外真实媒体做删除测试。

## 六、交付记录

### 1. 实现范围

- 入口与中文界面：`spooly/app.py`、`spooly/web/flow.py`、`spooly/web/library.py`、保留页面模板及导航/反馈控制器。首页直接播放；桌面侧栏、移动端顶部与菜单仅提供信息流和媒体库，旧文件夹等页面兼容跳转。旧音乐与下载 API 不注册，CLI 不启动下载工作线程。
- 媒体库管理：`spooly/web/library_management.py`、`spooly/services/media_import.py`、`spooly/static/library_management.js` 及媒体库模板/样式。支持逐文件导入结果、同名另存、搜索、重新扫描、预览、确认删除和回收站恢复。默认限制为每次 50 个文件、单文件 512 MiB、总请求 1 GiB，可通过实例配置调整。
- 全库随机：`spooly/services/shuffle.py`、`spooly/web/flow.py`。系统熵生成 256 位种子，按种子和媒体 URI 的 SHA-256 键形成稳定排列，以 `after` 游标分页。图片与视频共池，不使用类型配额、推荐权重或旧图集分组。
- 会话与播放器：`spooly/static/flow_session.js`、`spooly/static/flow_page_controller.js` 及共享控制器。同一浏览器保留当前 URI、随机种子及视频秒数；重新进入时校验媒体有效性，等待元数据后定位；保留拖动进度和跨条目清屏。

### 2. 本轮验收修复

1. 后台初始化视频或加载期间切到后台，返回前台时复用完整激活流程，恢复画面、声音状态并撤掉起播遮罩；同时处理后台延迟执行的动画帧。用户主动暂停的视频不会因切回前台自动播放。
2. 消除“上轮末项被固定到以后每轮末尾”的随机偏差。新轮只在首项与上轮末项碰撞时重抽种子，不再移动某一条媒体的排序位置。
3. 扫描、导入发布/回滚、删除和恢复使用同一实例的重入锁协调，避免旧扫描快照覆盖新索引，或重新插入已删除媒体。NAS 不支持硬链时使用独占复制，复制结束前不让扫描索引半文件；失败同步清理本次文件和索引，不覆盖竞争者的同名文件。
4. 回收站先写入并刷新恢复清单，再移动原文件。清单写入失败时原文件仍在原位置；移动已经完成时保留媒体和可用清单，不因异常清理误删。
5. 补齐旧 `/folder/<path>` 的媒体库重定向，并将停用模块、中文提示、尾页数量和模板上下文的旧测试调整到当前产品契约，保留相应行为验证。

### 3. 随机 API 与兼容说明

`GET /api/feed/mix` 接受 `size`、`page`、`seed`、`after`、`resume_uri`、`avoid_uri`，响应含 `items`、`seed`、`total`、`has_more`、`next_after`、`revision` 和 `resume_found`。

- 发起新轮时不传 `seed`，可传 `avoid_uri` 指定上一条媒体；存在至少两个有效候选时，返回的新种子保证首项不同。后续请求必须使用响应中的同一 `seed` 和 `next_after`。
- 显式 `seed` 始终重建同一排列，`avoid_uri` 不再改变该排列。这保证游标前的文件被删除后不会导致跳项。升级前保存过带避首排序的旧会话，其剩余顺序可能变化，但仍按 `resume_uri` 恢复当前媒体及秒数。
- 新文件位于当前游标之后时可加入当前轮，否则在下一轮出现；每轮重新洗牌覆盖全部当时可访问的媒体。候选数只有一个时允许连续播放该资源。

### 5. 环境限制与运行方法

- 本机未安装 Docker CLI，因此未执行 `docker build`，不宣称容器镜像构建已通过。
- 三项可选相似媒体实验测试因缺少 ffmpeg/ffprobe 跳过；现有 Requests 环境有缺少 `chardet`/`charset_normalizer` 的警告，测试仍可完成。
- 浏览器结果来自本机 Chrome 桌面与触屏模拟，尚未替代真机 iOS Safari 验收。媒体解码能力与首次有声自动播放继续受浏览器策略限制。
- 文件/索引并发协调作用于同一应用实例；当前默认 CLI 使用的线程服务器适用。同一媒体目录不要由多个独立写入进程同时管理。

从源码启动可使用：

```bash
.venv/bin/python -m spooly.run /path/to/media --host 127.0.0.1 --port 8000
```

将 `/path/to/media` 换为自己的媒体目录；使用说明及多目录配置见项目 `README.md`。本轮交付保留产品名称、Python 包名、CLI、环境变量及历史数据兼容性。
